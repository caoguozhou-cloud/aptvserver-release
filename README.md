# APTVserver

APTVserver 是 APTVMAN（iPhone / Apple TV 播放器）的家庭媒体服务器，装在你自己的 NAS 上。

装上之后：资料和封面在服务器上统一整理，所有设备看到的都一样；电视首页可以播放预告；
换台设备也能接着看；手机可以直接批准电视登录。**不装也能用 APTVMAN**，App 可以直接连 SMB / WebDAV，
APTVserver 只是可选的增强。

当前版本：**1.0.0**　·　免费使用　·　不收集任何数据

## 你需要

- 一台能运行 Docker 的 NAS：飞牛 fnOS、群晖（DSM 7.2+ Container Manager）、绿联、威联通、Unraid 等，x86 或 ARM 都可以；
- 1 GB 可用内存；
- 一个放影片的文件夹，以及一个空的「服务数据」文件夹（不要放在影片文件夹里面）。

## 安装（约 5 分钟）

1. **建文件夹**：在 NAS 文件管理里用自己的账号新建服务数据文件夹，例如 `docker/aptvserver`。
2. **新建 Compose 项目**：在 Docker / Container Manager 里新建项目，粘贴 [compose.yaml](compose.yaml)。
3. **改三处**（文件里标了「← 改」）：
   - `user`：你账号的 UID:GID。不确定的话在 NAS 终端运行 `id`，或在系统设置的用户详情里查看；
   - 影片文件夹的路径；
   - 服务数据文件夹的路径。
4. **启动**，等状态变成「健康」（首次启动要先下载镜像，网速慢时需要多等几分钟）。
5. 浏览器打开 `http://NAS的IP:8098/admin`，设置管理员账号和密码，再添加媒体库。
6. iPhone 上打开 APTVMAN → 添加来源，附近的 APTVserver 会自动出现；也可以在管理台「设备连接」扫码。

> 想自动识别影片并补齐封面，请在管理台「封面与资料」里填写自己的 TMDB API 读取令牌（免费申请）。
> 不填也能用：会读取文件夹里已有的 NFO 和海报。

### 各平台提示

| 平台 | 在哪里粘贴 compose | 路径怎么写 |
| --- | --- | --- |
| 飞牛 fnOS | Docker → Compose → 新增项目 | `/vol1/1000/影视` 这类路径，可在文件管理里右键「详细信息」查看 |
| 群晖 DSM | Container Manager → 项目 → 新增 | `/volume1/video`；UID 常见 `1026`，GID `100` |
| 其他 | `docker compose up -d` | 写宿主机上的绝对路径 |

## 下载很慢或失败？

compose 里默认用国内的阿里云地址。拉不动时，把两处 `image:` 换成注释里的 `ghcr.io` 地址，反过来也一样。
两个地址里是同一份镜像，摘要见每个版本的 Release 说明。

## 升级

1. 看 [Releases](../../releases) 里的更新说明；
2. 把 compose 里两处 `image:` 的版本号改成新版本；
3. 重新部署项目（飞牛「重建」、群晖「构建」）。

账号、观看记录和封面都在服务数据文件夹里，升级不会丢。服务器每天自动备份数据库，保留 7 份，
在管理台「系统 → 备份」里可以手动备份和恢复。**我们只发布固定版本号，不发布 `latest`**，所以不会出现你没注意时被自动升级的情况。

## 安全默认值

- 影片文件夹默认**只读**挂载。只有你把 `read_only` 改为 `false`，整理、文件管理等功能才能写入。
- 容器以你的普通账号运行，根文件系统只读，去掉了所有特权。
- 服务器不连接任何我们的服务器：只有你在设置里配置的 TMDB、MoviePilot 会收到请求。

## 遇到问题

管理台「系统 → 诊断」列出了后台任务、卡住的原因、磁盘和备份状态，内容不含路径和密钥，可以截图提问。
常见问题：

- **启动后一直不健康**：多半是服务数据文件夹不属于 `user` 里填的账号。在 NAS 上把这个文件夹的主人改成你的账号，再重启。
- **App 搜不到服务器**：确认 `aptvserver-discovery` 在运行，手机和 NAS 在同一个局域网；也可以直接扫码。
- **看不到某个文件夹**：只有挂载进 `/media` 的文件夹才可见，新增影片放进已挂载的文件夹即可。
